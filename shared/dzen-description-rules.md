# Дзен — правила **описания** (RSS `item/description`)

**HARD:** агент `excalibur-blog-description` читает этот файл целиком
перед записью `description-brief.json`.

Официальные источники (не по памяти — сверяй ссылки):

1. https://dzen.ru/help/ru/website/rss-modify.html — разметка RSS сайта  
   → элемент `description` внутри `item`: **«Описание статьи, которое
   будет отображаться в карточке материала в ленте»**.
2. https://dzen.ru/help/ru/export-content/export.html — техтребования
   экспортной ленты / примеры `item`: `title` и `description` — **разные**
   тексты; description без HTML-разметки; одно–два связных предложения.
3. https://dzen.ru/help/ru/requirements/card-preview.html — карточка в ленте  
   → кликбейт, мат, оскорбления, ALL CAPS, куча «?!», нечитаемые символы,
   код и ссылки в тексте карточки — **запрещены**.  
   (В Студии Дзена description иногда авто из первых фраз; **наш** путь —
   WordPress `post_excerpt` → RSS `<description>`, поэтому пишем сами.)
4. https://dzen.ru/help/ru/requirements/rules.html — общий канон контента
   (кликбейт карточки → ограничение показов).
5. `shared/dzen-content-rules.md` + `shared/rf-blocked-entities.json` —
   мат, РФ DENY, честность заголовка/карточки.

Связанный инцидент: `INC-20260805-2240` (description = обрезка лида →
двойной текст в Дзене). Последующий антипаттерн: description = title →
заголовок дважды на карточке.

---

## Куда попадает текст

```text
description-brief.json.description
  → article.meta.json description (+ meta_ab.description_*)
  → WP post_excerpt
  → RSS <item><description>
  → карточка Дзена / RSSLint
```

Тело статьи (`content:encoded` / `article.html`) — **отдельно**.
Description **не** дублирует ни `title`/`h1`, ни первый абзац body.

## Формат (наш канон под Дзен-карточку)

| Правило | Значение |
|---------|----------|
| Язык | русский, разговорный, для **новичков** |
| Длина | **80–180** символов с пробелами (цель ~120) |
| Объём | **одно** предложение (редко два коротких) |
| HTML | **запрещён** (plain text) |
| Эмодзи | **запрещены** |
| Точка в конце | допустима (это не title) |
| Повтор title | **запрещён** (exact и «почти exact») |
| Повтор opening | **запрещён** (не префикс / не обрезка первого `<p>`) |

### Содержание

- Честно говорит, **о чём материал и зачем читать**, без обмана ожидания.
- Имя продукта/темы — если оно в H1, можно один раз; без термин-карусели.
- Англицизмы / жаргон (CVE, endpoint, PoC, runtime, OSS, bearer…) —
  только если без них нельзя, и сразу бытовой перевод в том же предложении.
- Без кликбейта («вы не поверите», «шок», «секреты»), без «Срочно!» /
  «Эксклюзив», без служебных пометок («обновлено», «фоторепортаж»).
- Без мата и `@`-маски мата (Дзен).
- Без URL, без markdown, без кавычек-ёлочек и длинного тире «—»
  (как в остальном блоге: среднее «–» / дефис; прямые `"`).

### Self-check перед PASS

1. Прочитай title и description подряд вслух. Звучит как два разных текста?
2. Открой первый `<p>` статьи. Description — не его укороченная копия?
3. Поймёт ли новичок без DevOps-словаря?
4. Есть ли кликбейт / ALL CAPS / эмодзи / HTML? Вырежи.
5. Длина 80–180?

FAIL любого пункта → `verdict: FAIL` и новая попытка, не stamp.

## Антипаттерны (BLOCK)

```text
description == title
description == первые N символов opening
description пустой / < 80 / > 180
HTML / эмодзи / URL в description
кликбейт / мат / термин-дамп без перевода
```
